# Десктопное приложение (AppImage) — дизайн

Дополняет `2026-11-21-donation-goal-design.md`. Всё, что там описано про сбор донатов, цели, стиль и оверлей, не меняется.

## Зачем

Сейчас запуск такой: `uv run python -m donation_goal` в консоли, потом страница настроек в браузере.
Стример хочет обычное приложение: один `.AppImage`, запуск двойным кликом, окно настроек.
Порт 8000 конфликтует с локальным Django — нужен редкий порт.

## Цели

- Один файл `DonationGoal-x86_64.AppImage`, без установки Python и зависимостей.
- Окно приложения показывает текущую страницу настроек (`/`).
- Закрытие окна сворачивает приложение в трей; сбор донатов и оверлей для OBS продолжают работать.
  Выход — только через меню значка в трее.
- Порт по умолчанию `47321`, меняется в настройках (вступает в силу после перезапуска).

## Не цели

- Автозапуск при входе в систему, автообновление.
- Сборки под Windows/macOS, Flatpak.
- Отдельный от веб-страницы нативный интерфейс настроек.

## Анти-цели

- Оверлей в OBS пропадает, потому что окно случайно закрыли.
- Второй запуск поднимает второй сервер или падает с «порт занят» — должен просто показать уже открытое окно.
- Токены попадают в лог или в URL, видимый в OBS.

## Подходы

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A (выбран)** | PySide6 (Qt WebEngine + QSystemTrayIcon) + PyInstaller → AppImage | Всё на Python, надёжный трей на KDE, AppImage самодостаточен | ~200–250 МБ |
| B | pywebview (WebKitGTK) + pystray | ~40 МБ | Зависит от системного WebKitGTK, pystray на Wayland ненадёжен |
| C | Tauri (Rust) + Python-сайдкар | Родной трей и сборщик AppImage | Два языка и две сборки |

Выбран A пользователем.

## Устройство

### Процесс

- Главный поток — Qt (`QApplication`): окно с `QWebEngineView` на `http://127.0.0.1:<port>/`, `QSystemTrayIcon`.
- Фоновый поток — uvicorn с FastAPI-приложением (как сейчас, со своим asyncio-циклом).
  Окно открывает страницу только после того, как сервер ответил (опрос `/api/state` или флаг `server.started`).
- Выход: `server.should_exit = True`, дождаться потока (коллекторы останавливаются в lifespan), затем `QApplication.quit()`.

### Окно и трей

- `closeEvent` → `hide()` + `ignore()`. При первом сворачивании — уведомление из трея
  «Цель донатов работает в трее. Оверлей в OBS продолжает обновляться».
- Клик по значку — показать/скрыть окно. Меню: «Открыть настройки», «Скопировать ссылку для OBS», «Выход».
- Внешние ссылки (donationalerts.com и т.п.) и вход через DonationAlerts открываются в системном браузере
  (`QDesktopServices.openUrl`): там у стримера уже есть сессия DA.
- После OAuth-колбэка браузер показывает простую страницу «Готово, DonationAlerts подключён — можно закрыть вкладку»,
  а приложение подхватывает статус обычным опросом.
- Доступ JS к буферу обмена включён (`JavascriptCanAccessClipboard`), чтобы работали кнопки «Копировать».
- Иконка — своя SVG (полоса прогресса), используется для окна, трея и `.desktop`.

### Один экземпляр

- `QLocalServer` с именем `donation-goal-<uid>`. Если при старте удаётся подключиться к нему — отправить «show» и выйти.
- Если порт занят чужим процессом — окно с ошибкой «Порт N занят другой программой» и предложением указать другой порт
  (сохраняется в настройках, затем перезапуск).

### Данные и конфигурация

- Данные: `$XDG_DATA_HOME/donation-goal/app.db` (по умолчанию `~/.local/share/donation-goal/app.db`), а не папка запуска.
- Порт хранится в таблице `settings` (ключ `port`); переменная окружения `DONATION_GOAL_PORT` его перекрывает.
- Redirect URI для DonationAlerts строится из порта: `http://127.0.0.1:<port>/auth/da/callback`
  (на странице подключений уже показывается то, что отдаёт сервер).
- На вкладке «Подключения» — поле «Порт» с пояснением, что после смены нужно обновить ссылку в OBS
  и Redirect URL в приложении DonationAlerts.

### Режимы запуска

- `donation-goal` (и AppImage) — десктопное приложение.
- `donation-goal --headless` — только сервер, как сейчас (для разработки и отладки).
- `donation-goal --hidden` — сразу в трей (задел под автозапуск; сам автозапуск не делается).

### Сборка

- `packaging/build-appimage.sh`: PyInstaller (onedir, spec-файл) → AppDir (`AppRun`, `.desktop`, иконка) →
  `appimagetool` (скачивается в `build/tools/` при первой сборке) → `dist/DonationGoal-x86_64.AppImage`.
- PySide6: только нужные модули (`QtCore`, `QtGui`, `QtWidgets`, `QtWebEngineCore`, `QtWebEngineWidgets`, `QtNetwork`),
  чтобы не тащить весь Qt.

## Что оставлено исполнителю

- Точная раскладка модулей (`desktop.py`, `config.py`, `server.py` и т.п.).
- Внешний вид иконки.
- Как именно дождаться готовности сервера.

## Проверка

- Юнит-тесты: выбор пути данных (XDG), порт (настройка / переменная окружения / по умолчанию), redirect URI из порта,
  запуск и остановка серверного потока на свободном порту, «порт занят» определяется до старта Qt-окна.
- Ручная: собрать AppImage, запустить; окно открывается; закрытие → трей, оверлей продолжает обновляться;
  второй запуск показывает первое окно; «Выход» завершает процесс и освобождает порт.
