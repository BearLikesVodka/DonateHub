# DonateHub на Windows и автообновление — дизайн

Дата: 2026-11-22. Первый проект дорожной карты (дальше: общая лента донатов → очередь алертов и единый виджет
оповещений → мультичат Twitch + GoodGame → Meme Alerts → шрифты, темы, анимации).

## Зачем

DonateHub теперь нужен не только автору (Linux, KDE Wayland), но и другому стримеру на Windows. Его главная боль —
донаты с разных платформ перебивают друг друга; это решит проект «очередь алертов», но сначала программа должна
работать у него вообще. Новых версий будет много (лента, очередь, чат), поэтому друг должен получать их сам, без
пересылки файлов.

Успех: друг один раз ставит DonateHub установщиком на Windows 10/11, дальше программа сама предлагает обновления;
у автора на Linux всё работает как раньше и тоже обновляется.

## Цели

1. DonateHub собирается и работает на Windows 10 и Windows 11 (x86_64) с тем же поведением, что на Linux: окно
   настроек, трей, оверлеи для OBS, коллекторы DA и DX, вход в DA через OAuth, порт 47321, одна копия программы.
2. Установщик для Windows и AppImage для Linux собираются автоматически в GitHub Actions по тегу версии и попадают
   в выпуск GitHub вместе с данными для автообновления.
3. Автообновление на обеих платформах: программа сама узнаёт о новой версии и ставит её по согласию пользователя.
4. Тесты ядра и оболочки проходят и на Linux, и на Windows (в CI на каждый push и PR).

## Не цели

- macOS, Windows 7/8, ARM64, MSI-установщик.
- Платная подпись кода Microsoft. Первый запуск установщика покажет SmartScreen «Windows защитила ваш компьютер» —
  это принято; в README описать «Подробнее → Выполнить в любом случае».
- Автозапуск вместе с Windows.
- Новые функции для стримера — только перенос и доставка.

## Анти-цели (провал, даже если «работает»)

- Что-то сломалось или изменилось на Linux: папка данных, порт, трей ksni, AppImage, поведение окна.
- Обновление ставится или программа перезапускается без явного согласия: перезапуск посреди стрима обрывает
  оверлеи и коллекторы.
- Подменённое обновление может установиться: каждое обновление проверяется подписью.
- Повторный запуск на Windows молча «перехватывает» порт у уже работающей программы.

## Ограничения

- Стек остаётся: Rust 2024, axum + Tauri 2, общий `crates/core`, фронтенд в `static/` без сборщика.
- Самые свежие версии инструментов и зависимостей.
- Репозиторий публичный: https://github.com/BearLikesVodka/DonateHub. Коммиты только от
  `BearLikesVodka <33029026+BearLikesVodka@users.noreply.github.com>`.
- Секреты (ключ подписи обновлений и пароль к нему) — только в секретах GitHub Actions и у автора локально
  (`~/.tauri/donatehub.key`), никогда в репозитории.
- Проверка на Windows: ноутбук автора с Windows 10 и виртуалка Windows 11 (будет SSH-доступ для сборки и тестов).

## Подходы к сборке (выбрано: A)

- **A. GitHub Actions (выбрано).** Тег `vX.Y.Z` → сборка на `windows-latest` (NSIS) и Linux (AppImage), подпись
  обновлений, черновик выпуска с `latest.json`. Честная сборка и тесты на настоящей Windows, бесплатно для
  публичного репозитория, компьютер автора не занят.
- B. Кросс-сборка на Linux (cargo-xwin) и ручная загрузка выпуска. Отклонено: кросс-сборка Windows в Tauri
  экспериментальная, тесты под Windows так не прогнать.

Доставка (выбрано: автообновление через выпуски GitHub, а не пересылка установщика вручную): версий будет много.
Публичный репозиторий выбран, потому что автообновление скачивает без авторизации; код и так под MIT.

## Решения

### Платформенные различия в оболочке (`src-tauri`)

| Что | Linux (как сейчас) | Windows |
|---|---|---|
| Трей | ksni (StatusNotifierItem) | встроенный трей Tauri: левый клик — показать/скрыть окно, то же меню из трёх пунктов |
| Уведомления | notify-rust | системные toast-уведомления Windows 10/11 (те же тексты) |
| Буфер обмена из окна | настройка webkit2gtk `javascript-can-access-clipboard` | WebView2 сам разрешает `navigator.clipboard.writeText` на `http://127.0.0.1` — проверить, при необходимости добавить запасной путь |
| Завершение | SIGTERM/SIGINT → корректная остановка | Ctrl+C в `--headless`; в GUI — «Выход» в трее и выход из сеанса Windows |
| Консоль | — | GUI-сборка без чёрного окна консоли; `donatehub.exe --headless` из cmd/PowerShell всё равно печатает адреса настроек и оверлея |

Linux-специфичные зависимости (ksni, webkit2gtk, Linux-фичи arboard) подключаются только для Linux; общий код
трея (меню, тексты, действия) один на обе платформы. Структура модулей — на усмотрение исполнителя.

### Ядро (`crates/core`)

- **Папка данных.** Linux без изменений (`$XDG_DATA_HOME/donatehub` или `~/.local/share/donatehub`, перенос из
  `donation-goal`). Windows: `%APPDATA%\DonateHub` (Roaming), без переноса старых имён (там их не было).
- **Порт.** На Windows `SO_REUSEADDR` позволяет занять уже занятый порт, поэтому и проверка «порт свободен», и
  сервер на Windows используют эксклюзивную привязку (`SO_EXCLUSIVEADDRUSE` или без reuse). Поведение «порт занят
  → диалог с предложением другого порта» одинаково на обеих платформах. На Linux всё как сейчас.
- Сервер слушает только `127.0.0.1`, поэтому брандмауэр Windows не спрашивает разрешения.

### Установщик Windows

NSIS, установка для текущего пользователя (без прав администратора), язык — русский, ярлык в «Пуск». WebView2: если
его нет, установщик докачивает (режим по умолчанию Tauri). Удаление программы не трогает папку данных.

### Автообновление

- `tauri-plugin-updater`, источник: `https://github.com/BearLikesVodka/DonateHub/releases/latest/download/latest.json`.
  Работает и для NSIS-установки на Windows, и для AppImage на Linux.
- Обновления подписаны ключом Tauri. Открытый ключ — в `tauri.conf.json`, закрытый и пароль — в секретах GitHub
  `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Ключ генерирует исполнитель
  (`cargo tauri signer generate`), копия — у автора в `~/.tauri/donatehub.key`.
- Проверка: при запуске и раз в 6 часов. Если есть новая версия:
  - в окне настроек появляется заметная, но не мешающая плашка «Доступна версия X.Y.Z» с кнопкой «Обновить»;
  - один раз на версию — уведомление в трее.
- «Обновить» скачивает, ставит и перезапускает программу. Без нажатия ничего не ставится и не перезапускается.
- Ошибки проверки (нет сети, GitHub недоступен) тихие: пишутся в лог, плашка не появляется.
- Окно настроек — это страница локального сервера без IPC Tauri (так задумано и остаётся). Значит, кнопка
  «Обновить» и состояние «есть обновление» идут через HTTP API локального сервера, а сам апдейтер живёт в
  оболочке Tauri. Ядро даёт оболочке точку подключения («проверить/установить обновление»), в `--headless` её нет —
  там API отвечает, что обновления недоступны. Форма этой точки — на усмотрение исполнителя.
- Новые эндпоинты подчиняются тем же правилам безопасности, что и остальные: Host только localhost, запись — только
  с той же страницы (Origin).

### Версии и выпуски

- Первая версия с Windows — `0.3.0`. Номер версии хранится в одном месте (или CI проверяет, что тег совпадает со
  всеми местами, где он записан).
- `.github/workflows`:
  - на push и PR: `cargo test --workspace`, clippy, JS-тесты (`node --test tests/js`) на Linux и Windows;
  - на тег `v*`: сборка Windows (NSIS) и Linux (AppImage), подпись, **черновик** выпуска с `latest.json`.
- Выпуск публикуется вручную после проверки установщика на виртуалке Windows 11 и ноутбуке Windows 10 — так
  непроверенная версия не прилетит другу автообновлением.
- Проверка обновления до публикации (решение автора дизайна): адрес `latest.json` можно подменить
  переменной окружения `DONATEHUB_UPDATE_ENDPOINT` (в том числе в релизной сборке; подпись проверяется всегда).
  Для проверки скачиваются файлы черновика, `latest.json` правится на локальные адреса и раздаётся локальным
  HTTP-сервером на тестовой машине. У 0.2.0 апдейтера нет, поэтому проверка «старая → новая» начинается с 0.3.1;
  для 0.3.0 проверяется только установка начисто.
- Ключи и выпуск (решение): ключ подписи и случайный пароль генерирует исполнитель; секреты GitHub ставит сам через
  `gh secret set` (не печатая значения); локально ключ — `~/.tauri/donatehub.key`, пароль —
  `~/.tauri/donatehub.key.password`, оба `chmod 600`. Автор сам делает резервную копию ключа и пароля (менеджер
  паролей): без них уже установленные копии никогда не смогут обновиться. План заканчивается собранным в CI
  черновиком `v0.3.0` (тег ставит исполнитель); публикует автор после ручной проверки.
- В README: установка на Windows (SmartScreen), как выпускать версию (тег → проверка → публикация черновика).

## Проверка

- Автотесты на Linux и Windows в CI: путь к папке данных на обеих платформах, эксклюзивная привязка порта на Windows
  (вторая привязка к занятому порту не проходит), API обновлений (нет оболочки → «недоступно»; есть → состояние и
  установка вызывают оболочку), правила Host/Origin для новых эндпоинтов.
- Windows-часть разработки опирается на CI (`windows-latest`); если к моменту исполнения есть SSH на виртуалку
  Windows 11 — исполнитель использует её для сборки, тестов и отладки (порт, буфер обмена, уведомления). GUI по SSH
  не проверить, поэтому ручные пункты ниже выполняет автор по чек-листу исполнителя.
- Вручную на Windows 11 (виртуалка) и Windows 10 (ноутбук):
  1. установка из черновика выпуска;
  2. окно, трей (клик, меню), уведомление о сворачивании в трей;
  3. оверлей в OBS, «Копировать», вход DA, подключение DX, тестовый донат;
  4. второй запуск показывает окно первой копии;
  5. «Выход» освобождает порт;
  6. обновление со старой версии на новую через плашку (начиная с 0.3.1, см. «Версии и выпуски»).
- Linux: прежние тесты зелёные, AppImage из CI запускается, обновление AppImage через плашку.

## Оставлено исполнителю

Структура модулей платформенного кода, выбор crate для toast-уведомлений Windows, способ показать вывод
`--headless` в консоли Windows, форма точки подключения апдейтера к ядру, вид и место плашки обновления в
существующем окне настроек (в стиле текущего интерфейса), конкретные actions в GitHub Actions и версия Ubuntu
для сборки AppImage (такая, чтобы AppImage запускался на актуальных дистрибутивах).
