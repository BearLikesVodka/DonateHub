# Универсальная цель донатов (DonationAlerts + DonateX) — дизайн

## Зачем

Стример принимает донаты на двух платформах: DonationAlerts (DA) и DonateX. Встроенная цель
каждой платформы видит только свои деньги. Нужна одна цель-оверлей для OBS (браузерный источник),
которая суммирует донаты с обеих платформ, настраивается по внешнему виду не хуже виджета DA
и хранит историю целей.

## Цели

- Одна активная цель: название, сумма-цель (RUB), дата начала, опциональная дата окончания.
- Сумма цели = сумма донатов с DA и DonateX с момента старта цели (до окончания, если задано)
  + ручная корректировка.
- Оверлей `http://localhost:8000/overlay` — горизонтальная полоса, обновляется в реальном времени.
- Страница настроек `http://localhost:8000/` с живым превью (как «Дизайн виджета» у DA).
- История целей: название, собрано / цель, даты начала и окончания.
- Подключение платформ из страницы настроек: DA через OAuth, DonateX через внешний токен.

## Не цели (v1)

- Вертикальные индикаторы (структура стилей должна позволять добавить их позже).
- Цели самих платформ (DA goals, DonateX GoalUpdated) — не используются.
- Алерты, звук, список последних донатов.
- Несколько одновременно активных целей.
- Доступ извне компьютера стримера, многопользовательский режим.
- Порт на Rust.

## Анти-цели

- Сумма на стриме неверна (двойной учёт, потеря донатов при обрыве связи) — хуже, чем отсутствие виджета.
- Превью отличается от того, что видно в OBS.
- Токены видны в URL оверлея или в его HTML.

## Ограничения

- Python 3.15+ (через uv), FastAPI + uvicorn, httpx, websockets. SQLite (stdlib `sqlite3`). Фронтенд — чистые HTML/CSS/JS без сборки.
- Сервер слушает только `127.0.0.1`.
- Запуск одной командой (`uv run` или `python -m ...`), конфиг и БД — в папке проекта (`data/`).
- Лимиты API: DA — 60 запросов/мин на приложение; DonateX — 20 rps, 10 подключений к хабу/сек с IP.

## Подходы

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A (выбран)** | Python FastAPI + чистый HTML/JS | Один процесс, без сборки, быстро писать | Форма настроек на чистом JS многословнее |
| B | Python + Svelte/Vue | Приятнее строить UI | Node.js, шаг сборки, второй стек |
| C | Rust (axum) | Один бинарник | Заметно дольше писать (OAuth, SignalR, БД) |

Выбран A пользователем: важнее скорость написания; нагрузка ничтожная.

## Устройство

```
DA Centrifugo WS ──┐
                   ├─► collectors ─► SQLite (donations, goals, settings) ─► broadcaster ──WS /ws──► overlay.html (OBS)
DonateX SignalR ───┘                                                                     └──────► settings page (iframe превью)
```

### Хранилище (SQLite)

- `donations(platform, external_id, username, amount, currency, amount_rub, created_at UTC, is_test, raw_json)`,
  уникальный ключ `(platform, external_id)` — дедупликация (`INSERT OR IGNORE`).
- `goals(id, title, target_rub, started_at, ends_at NULL, closed_at NULL, manual_adjust_rub)`.
  Активная цель — та, у которой `closed_at IS NULL` (не более одной).
- `settings(key, value_json)` — стиль виджета, токены платформ, OAuth-данные DA.
- Собрано по цели = `SUM(amount_rub)` по донатам с `is_test = 0` и `started_at <= created_at < COALESCE(closed_at, ends_at, +∞)` + `manual_adjust_rub`.
  История считается тем же запросом — отдельно суммы не хранятся.

### DonationAlerts

- Пользователь регистрирует своё приложение на `donationalerts.com/application/clients`
  с redirect URI `http://127.0.0.1:8000/auth/da/callback`, вводит client_id/secret на странице настроек
  (на странице — пошаговая инструкция).
- OAuth authorization code: scopes `oauth-user-show oauth-donation-subscribe oauth-donation-index`.
  Хранить access/refresh токены и `expires_at`, обновлять заранее через `grant_type=refresh_token`.
- Realtime: `GET /api/v1/user/oauth` → `id`, `socket_connection_token`; WS
  `wss://centrifugo.donationalerts.com/connection/websocket` → connect (`{"params":{"token":...},"id":1}`) →
  получить `client` → `POST /api/v1/centrifuge/subscribe` с каналом `$alerts:donation_<id>` → subscribe (`method: 1`).
  Входящие push содержат объект доната (точное вложение проверить на живом сообщении — парсер должен
  находить объект доната в `result.data.data` и логировать незнакомую форму).
- Догонка после (пере)подключения: `GET /api/v1/alerts/donations` страницами, пока `created_at` не станет
  старше начала активной цели или последнего известного доната.
- Валюта: в API DA нет суммы в рублях. Не-RUB пересчитывается по курсу ЦБ (`https://www.cbr-xml-daily.ru/daily_json.js`,
  кэш на сутки, последний удачный курс сохраняется). `created_at` — UTC, парсить форматы с `:` и `.`.

### DonateX

- Внешний токен из кабинета (Настройки → API и доступ), вводится на странице настроек.
- Realtime: SignalR-хаб `https://donatex.gg/api/public-donations-hub?access_token=<token>`, JSON-протокол.
  Свой минимальный клиент: `POST .../negotiate?negotiateVersion=1` → WS, handshake `{"protocol":"json","version":1}\x1e`,
  обработка сообщений type 1 (`DonationCreated`, `DonationRerun`), ping type 6, close type 7.
  Если свой клиент окажется ненадёжным — заменить на библиотеку `pysignalr` (решение исполнителя).
- Сумма: поле `amountInRub`. `isTest = true` сохраняется, но не считается.
- Догонка: `GET /api/v1/donations?take=100&sortOrder=NewestFirst&skip=...` (Bearer), пока не дошли до
  донатов старше границы.

### Общее для коллекторов

- Каждая платформа — отдельная asyncio-задача: подключение, чтение, при ошибке — экспоненциальный backoff
  (1 → 60 с), после переподключения — догонка через REST. Падение одной платформы не трогает другую.
- Статус платформы (подключено / ошибка / не настроено + текст ошибки) показывается на странице настроек.

### Стиль виджета

JSON-объект в `settings`, со значениями по умолчанию как на скриншоте DA:

- Элементы: заголовок (сверху / снизу / скрыт), прогресс (внутри / сверху / снизу / скрыт),
  формат прогресса (`50%`, `5 000 RUB`, `5 000 RUB (50%)`, `5 000 / 10 000 RUB`, `5 000 / 10 000 RUB (50%)`),
  оставшееся время (сверху / снизу / скрыто), границы сбора (0 и цель под полосой), подложка + её цвет.
- Индикатор: высота, радиус, толщина и цвет обводки, фон (цвет или градиент), заливка (цвет или градиент из 2 цветов + угол).
  Размеры в `vw`, чтобы масштабироваться вместе с размером источника в OBS.
- Шрифт для каждого из трёх текстов: семейство (список Google Fonts + свободный ввод имени системного шрифта),
  размер, жирность, курсив, цвет, обводка/тень текста.
- Пресеты: 4–6 горизонтальных пресетов как JSON-файлы; клик применяет пресет к форме (без сохранения).
- Значения `> 100%` полоса ограничивает 100%, текст показывает реальную сумму.

### Оверлей и превью

- `overlay.html` + `overlay.js` + CSS — один рендерер, стиль применяется через CSS-переменные и классы.
- Оверлей подключается к `WS /ws`, получает `{goal, collected_rub, style}` при подключении и при любом изменении;
  при обрыве переподключается. Фон страницы прозрачный.
- Превью на странице настроек — тот же `overlay.html` в `<iframe>` с параметром `?preview=1`:
  несохранённый стиль передаётся через `postMessage`, данные — текущая цель (или тестовая 5 000 / 10 000).
  Переключатель «игровой фон» под превью.
- «Сохранить» → `PUT /api/style` → рассылка всем оверлеям.

### Страница настроек

Вкладки: **Цель** (текущая цель: создать / изменить / завершить, ручная корректировка), **Дизайн**
(превью, пресеты, вкладки «Элементы» / «Индикатор» / «Шрифты»), **История** (список завершённых целей),
**Подключения** (DA OAuth, токен DonateX, статусы). Визуальный стиль — тёмный, как у DA.

## Что оставлено исполнителю

- Структура модулей, точные эндпоинты JSON API между страницей настроек и сервером.
- Конкретный список Google Fonts и набор пресетов.
- Как отображать оставшееся время (формат `2д 4ч`, `04:12:33` и т.п.).

## Проверка

- Юнит-тесты: парсинг донатов обеих платформ (на примерах из документации), дедупликация, подсчёт суммы цели,
  конвертация валют, форматирование прогресса.
- Ручная проверка: тестовый донат DonateX (`POST /api/v1/test-donation`) — не должен попасть в сумму, но должен
  появиться в логе; эмуляция донатов через отладочный эндпоинт; просмотр оверлея в браузере (Playwright-скриншот).
