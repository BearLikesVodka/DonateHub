# DonateHub Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Переписать DonateHub с Python на Rust (axum + Tauri 2 + ksni) с полным паритетом поведения и совместимостью данных, собрать лёгкий AppImage, удалить Python.

**Architecture:** Cargo workspace: `crates/core` (`donatehub-core`: всё без GUI — SQLite, коллекторы, axum-сервер) и `src-tauri` (`donatehub`: бинарник — окно Tauri на `http://127.0.0.1:<port>/`, трей ksni, один экземпляр, CLI). Фронтенд встраивается в бинарник и не меняется.

**Tech Stack:** Rust 1.99 / edition 2024, tokio, axum, rusqlite (bundled), reqwest + tokio-tungstenite (rustls), chrono, serde_json, tracing, rust-embed, Tauri 2 (+ single-instance, opener), ksni, notify-rust, arboard, rfd. Тесты: `cargo test`, `wiremock` для HTTP-моков, локальный `tokio-tungstenite` сервер для WS-моков.

**Spec:** `docs/superpowers/specs/2026-11-21-rust-port-design.md` (+ `2026-11-21-donation-goal-design.md`, `2026-11-21-desktop-app-design.md`). Эталон поведения — `src/donatehub/*.py` и `tests/*.py` на этой ветке до задачи 12.

## Global Constraints

- Версии: последний stable Rust, edition 2024; крейты — `cargo add` без версии (самые свежие), Tauri 2.x.
- Только Linux. Linux-специфика трея — в `src-tauri/src/tray.rs`.
- Сервер слушает только `127.0.0.1`; `DEFAULT_PORT = 47321`; `PORT_ENV = "DONATEHUB_PORT"` (1024–65535) > `settings.port` > 47321.
- Данные: `$XDG_DATA_HOME/donatehub/app.db` (иначе `~/.local/share/donatehub/app.db`); старая `donation-goal` рядом переносится `rename`, если новой нет.
- Схема SQLite — дословно `SCHEMA` из `src/donatehub/store.py`. Даты в БД — `%Y-%m-%dT%H:%M:%S%.6f+00:00` UTC.
- JSON API, коды ответов и WS-сообщения — как в Python; ошибки — `{"detail": "<русский текст>"}`, ошибки валидации тела — 422 с `detail`-массивом (фронтенд показывает «Проверьте заполнение полей»).
- Тексты для пользователя — по-русски, дословно как в Python (страница DA_DONE_PAGE, ошибки, уведомление трея).
- Токены никогда не попадают в логи, тексты ошибок (`redact`) и `/api/state`.
- Тестовые запуски — с временным `XDG_DATA_HOME`, портом ≠ 47321 и `APPIMAGELAUNCHER_DISABLE=1`; живую базу пользователя не трогать.
- Каждая задача: `cargo test --workspace` и `cargo clippy --workspace --all-targets -- -D warnings` зелёные перед коммитом. Коммиты с trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Правило переноса тестов:** когда задача говорит «перенести `tests/test_x.py::test_name`», это Rust-тест с тем же именем, теми же входными данными и теми же проверками. Сначала тест (RED), потом код.

## Review Focus

1. База, записанная Python-версией (даты с `+00:00`/`.000000`, `amount_rub` NULL, JSON в `settings`), читается Rust без ошибок, а новые строки сортируются вместе со старыми → `store_reads_python_written_rows` (Task 2).
2. `Host: 127.0.0.1:47321` и `localhost:47321` пропускаются, `Host: evil.example` → 400; `Origin: http://evil.example` на POST → 403, а без `Origin` — проходит (так ходят curl и OBS) → `host_with_port_allowed`, `test_foreign_host_rejected`, `test_cross_site_post_rejected` (Task 8).
3. Ошибки отдаются в форме, которую понимает `admin.js` (`detail` — строка или массив) → `errors_have_detail` (Task 8).
4. Оборванное WS-соединение оверлея не ломает рассылку остальным → `broadcast_drops_dead_clients` (Task 5).
5. Выход из приложения при живых коллекторах и открытых WS освобождает порт за ≤ 10 с → `test_server_thread_stop_releases_port` с подключённым WS-клиентом (Task 9).
